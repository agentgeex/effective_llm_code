# 视频识别游泳者溺水（§11.1）

## 这个案例干什么

把一段泳池视频变成「可判断的结构化数据」，再用有限状态机 + 规则判断某个泳者是否疑似溺水。

链路是四步：

```
视频 → 抽帧 → 场景切分/关键帧 → 每帧的检测结果 → 状态机判定（NORMAL / SUSPECT / ALERT）
```

这条链里，**视频预处理和状态机都是可以本地跑通、可复现的**；真正的关键点检测需要模型权重（见「依赖什么」）。

## 对应书哪一节

第 11 章 §11.1「视频识别游泳者溺水」。

## 怎么跑

```bash
# 1) 合成一段带已知切点的测试片（需要 ffmpeg）
python ch11/cases/video_probe/make_clip.py

# 2) 跑预处理链：抽帧 → 场景切分 → 关键帧 → 音频轨
python ch11/cases/video_probe/probe.py

# 3) 关键帧 OCR 并与标准答案比对（字符级 diff）
python ch11/cases/video_probe/ocr_frames.py

# 4) 把结果汇成可读报告
python ch11/cases/video_probe/report.py
```

跑完看 `ch11/cases/video_probe/outputs/`（这个目录不入库，跑一遍就有了）。
`fade_test.py` 是对切点检测的单元级测试，可以直接跑。

## 依赖什么

| 依赖 | 用途 | 没有它会怎样 |
|---|---|---|
| `ffmpeg`（命令行） | 合成测试片、抽帧、抽音轨 | `make_clip.py` / `probe.py` 直接报错，提示装 ffmpeg |
| `opencv-python`（`cv2`） | 读帧、场景差异计算 | `ImportError: No module named 'cv2'` |
| `numpy` | 帧差与统计 | 同上 |
| 关键点检测模型权重 | 判断是否溺水 | **本仓库不带**。没有它，前置预处理链照常跑，判定环节无法执行 |

**没有模型权重时**：这个案例能演示「视频 → 结构化帧数据」这一段，不能演示「判定溺水」那一段。文件头注释里没有把它标成无条件可跑，就是这个原因。

## 数据从哪来

- **测试片**：`make_clip.py` 用 ffmpeg 现合成，不依赖任何外部素材。
- **标准答案**：`data/clip_spec.json`（合成时就写好的切点/画面参数，用于比对）。
- **真实泳池视频**：仓库不带。涉及真人影像，请自行准备并注意授权与隐私。

## 提醒

这是**技术演示**。真实场景的溺水识别要考虑水面反光、遮挡、多人交叉、摄像机视角，并且必须有人工复核与现场救生流程兜底 —— 不要把任何模型的输出当作唯一判据。
